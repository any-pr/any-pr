实验仓库

自动合并
Pull Request 条例

在无人工审查的情况下，接收、审查并合并每一个 Pull Request。

仓库 any-pr · 执行文件 .github/workflows/auto-merge.yml

鉴于本仓库实行无限制贡献政策；且

鉴于有必要确立统一规则，使 Pull Request 得以在无人工审查的情况下被接收、审查并合并；

兹通过以下条例，对所有贡献者具有约束力。

第一条 — 总则

第 1 节 目的

本条例规定提交至本仓库的 Pull Request 在何种条件下被自动合并。任何阶段均不进行人工审查。

第 2 节 定义

  • (a) “Pull Request” 或 “PR”：指为合并至基础分支而提交的一组变更。
  • (b) “工作流”：指维护于 .github/workflows/auto-merge.yml 的自动化执行文件。
  • (c) “许可文件”：指任何构成许可协议的文件，包括 LICENSE、LICENCE、UNLICENSE、COPYING、COPYRIGHT 及其带后缀变体，以及 LICENSES/ 目录的内容。
  • (d) “禁止文件”：指临时文件、系统残留、缓存、构建输出、二进制文件，以及凭据或机密材料；明确标记的示例模板除外。
  • (e) “README”：指本文档，即 README.md 及其所有变体与本地化版本。

第二条 — 自动合并

第 1 节 强制合并

任何未被标记为草稿、且满足第三条要求的 Pull Request，应立即以 squash 提交方式合并，并在权限允许时删除其源分支。

第 2 节 草稿 Pull Request

带有草稿标记的 Pull Request 在撤销该标记之前不予合并。

第 3 节 合并失败

若因与基础分支冲突而无法合并，应在该 Pull Request 上发布通知，贡献者须变基并重新提交。

第三条 — 强制关闭事由

Pull Request 存在下列情形之一者，应关闭且不予合并：

(a) 修改、新增、删除或重命名 .github/ 下的任何文件或目录。

(b) 修改任何许可文件或 README；删除或重命名均构成修改。

(c) 引入一个或多个禁止文件。

(d) 引入符号链接或子模块，此判定通过检查 git 文件模式作出。

(e) 引入二进制内容，无论其命名如何，此判定通过检查底层 git 对象作出。

(f) 超出第四条规定的尺寸限制。

第四条 — 尺寸限制

文件数

一个 Pull Request 不得修改超过 20 个文件。

总行数

计行变更总数不得超过 500 行。

单文件

任何单个文件不得超过 300 行变更。

豁免

lockfile、vendor/、压缩文件与快照豁免计行，但仍受文件数限制。

第五条 — 禁止直接推送

第 1 节 任何人不得直接向 main 分支推送提交。所有变更须仅通过 Pull Request 提交。

第 2 节 任何未经关联已合并 Pull Request 而到达 main 的提交，应使该分支恢复至该次推送前的状态，并记录该事件。

第六条 — 免责声明

第 1 节 仓库性质 本仓库是一项自动化治理实验。它并非、亦不应被解释为良好工程实践的典范。

第 2 节 无审查 本仓库合并的所有内容均未经审查。贡献者与使用者须知，其内容可能包括但不限于垃圾信息、无意义内容、冲突编辑、无法运行的代码，以及品味可疑的材料。本条例仅过滤特定危害，不对质量、效用或意图作出任何判断。

第 3 节 无担保 本仓库中的任何代码均不得被执行、部署或依赖。每个文件均应视为不可信。

第 4 节 尽力执行 本条例的执行由响应仓库事件的自动化工作流完成。此类执行属尽力而为，不构成访问控制，亦不保证仓库在任何给定时刻的状态。

第 5 节 贡献者责任 每位贡献者对其 Pull Request 的内容承担全部责任。贡献者不得提交非法、有害、侵权或损害其自身声誉的材料；提交内容可公开归属于其作者。

第 6 节 条款接受 打开 Pull Request 的行为即构成接受：该 Pull Request 可能在任何时候被后续贡献者合并、关闭或以其他方式更改。此即本实验之目的。
