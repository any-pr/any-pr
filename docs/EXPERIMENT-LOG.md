## 三、治理机制解剖

工作流由两段逻辑构成：

1. **审查与合并**：对每一份非草稿之 PR，逐项检查第三条第 (a)–(f) 项，通过者以压缩提交合并，并删除源分支。
2. **直推回滚**：对 `main` 之每次推送，核查其提交是否均源自已合并之 PR；若有可疑提交，则以 `--force-with-lease` 回滚，并开列 issue 存证。

值得注意的是：**该机制不评价内容质量**。此非疏漏，而是明文的自我限制 —— 第六条第 2 节载明，规则"仅过滤指定危害，并不对质量、效用或意图作出任何判断"。

## 五、初步观察

1. **规则确如其所述地运作**：全期唯一被关闭者（#2），正因触碰受保护文件。规则未越权，亦未失职。
2. **但过滤指定危害，并不产生秩序**：二十份 PR 中，具有工程意义者为零。仓库内容为垃圾文本、虚构项目、图片与问候语之集合。
3. **边缘行为自然出现**：以命名绕行（#3）、以目录绕行（#6–#8，于仓库内嵌入另一个"仓库"）等做法，均由参与者自发探索而出，且未受阻拦。
4. **主持人缺席**：自首分钟后，主持人再未出现 —— 无评论、无审查、无回应。这使得本实验在事实上成为**无治理**，而非"自动化治理"。
5. **实验已成为目的本身**：参与者并非为解决某问题而来，而是为参与该实验而来。仓库的价值不在其内容，而在其存在。
