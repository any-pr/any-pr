## 一、审查范围与说明

本意见书不对《规定》之政策取向作任何评价。第六条第 1 节已自认："本仓库是一项自动化治理实验。它不是、也不应被解释为良好工程实践的典范。"审查因此仅及于**文本之内在一致性**与**执行之实际效果**。

审查所依据之材料，均取自公开可查之提交记录与工作流定义。

## 二、已认定之漏洞

### 2.1 自称不可修订之文书，实则未受任何保护

`docs/CONTRIBUTING.md` 开篇载明：

> 本文档不得修订、取代或废止。任何修改它的拉取请求都将被自动关闭。

然《规定》第三条第 (b) 项所保护者，仅为**许可文书（License Instrument）**与**README**。二者之定义（第一条第二款 (c)、(e) 项）均不涵盖 `docs/CONTRIBUTING.md` —— 其名称中并无 "README" 字样，其路径亦不在 `.github/` 之下。

**实证**：拉取请求 **#4**（`lemonhub-io`，2026-10-02，标题 "Fix docs"）修改了该文件，改动两处标点断句（`+2/-2`），随后经工作流**自动合并**，成为压缩提交 `e776dbb`。

**认定**：该声明系无强制力之自我宣示。其效力不高于任何一份普通文档。

### 2.2 "README" 之定义未涵盖大小写与形近字

第一条第二款 (e) 项定义 README 为 "`README.md` 及其所有变体（`README`、`README.rst`、本地化变体如 `README.zh-CN.md`，以及在任何深度以此命名的文件）"。

该定义存在两处未决：

1. **大小写**：工作流对 `.github/` 之匹配，于注释中明示为 "case-insensitive"；对 README 则未作同等声明。故 `readme.md`（全小写）是否落入保护范围，文本上无从断定。
2. **形近字（homoglyph）**：定义未规定 Unicode 规范化。以 `RЕADME.md`（第二字符为西里尔字母 Е，U+0415）为名之文件，在视觉上与受保护文书无从分辨，但于二进制层面并非同一字符串。

**认定**：上述两处构成定义之边界模糊。其是否可被利用，宜由工作流以实际行为予以澄清。

### 2.3 第四条第四款之行数豁免，实为规避通道

第四条第 4 款规定：

> 生成内容和 vendored 内容——包括锁文件、`vendor/` 的内容、压缩文件和快照——就第 2 节和第 3 节规定的行数而言豁免，但仍受第 1 节规定的文件数约束。

即：**第四条第 2 款（合计 500 行）与第 3 款（单文件 300 行）对 `vendor/` 之下的一切内容完全失效**。而第 1 款（20 文件）仍然适用。

**认定**：现行规定在字面上允许单个拉取请求引入**行数不设上限**的文本内容，仅需将其置于 `vendor/` 之下。所谓"大小限制"，于该路径上并无限制可言。

### 2.4 第三条各项之竞合与次序不明

第三条第 (b) 项禁止**修改** README；第 (c) 项禁止引入禁止文件，而禁止文件之定义（第一条第二款 (d) 项）通篇未及 `.md` 类文档。

**认定**：故一个拉取请求可自由**创建**一份与 README 文本相同、旨趣相同之新文档，只要其不以 "README" 命名、不改动 README 本身，即不落入任何禁止事由。

**实证**：拉取请求 **#3**（`MFSCelebrate`，2026-10-02）即于仓库根目录新增名为 `中文 Readme 点 Contributing` 之文件 —— 该文件内容为空，其全部意义在于文件名本身。此举已表明"以命名绕行"之路径现实可行，且未被工作流拦阻。

### 2.5 第五条之执行存在竞态窗口

第五条禁止直接推送 `main`，其执行见工作流末尾之回滚逻辑。该逻辑自述：

> main moved past ${AFTER} while inspecting — not rewinding to avoid losing newer history.

即：若在违规推送之后、工作流完成检查之前，另有正常经 PR 之合并发生，则工作流将**放弃回滚**，以保全较新之历史。

**认定**：第五条之执行存在时间窗口。违规推送在特定竞态条件下，可获**事实上的追认**，且仅以一条 issue 作为记录。

## 三、修正案建议

1. **扩充保护客体**：于第三条第 (b) 项下增设"贡献文书（Contributing Instrument）"类别，涵盖 `docs/CONTRIBUTING.md` 及其所有译本，使其自称之不可修订性名实相符。
2. **明确文件名比较规则**：就 README 之匹配，明定是否区分大小写，并规定先经 Unicode NFKC 规范化再行比较。
3. **封堵豁免通道**：就第四条第 4 款之豁免内容，另设总量上限（如总字节数），使"大小限制"名实相符。
4. **消除竞态**：为第五条之回滚设置重试或排队机制，使违规推送不因时序而获追认。

## 四、结语

本意见书依第六条第 2 节之精神出具：本库所合内容均未经审查，本意见亦不例外。

本意见书之提交行为本身，即构成对本库规则适用边界之一项检验。其被合并或被关闭，皆为本实验之有效数据。
